# Motor 与实时控制

`motor.h/.c` 拥有命令验证、生命周期与活动目标；`control_runtime.h/.c` 在确定性采样边界
拥有反馈、估计、待执行命令和控制流水线。后台读取协议无关的 `MotorSnapshot` 副本，
不直接修改实时算法历史。长期边界见 [总体架构](../../../ARCHITECTURE.md)。

## 有限静态定向核心

`rotor_alignment.h/.c` 是 Motor 内部可选的有限试验计算器，尚未装配到实际功率路径，
不新增公共 RUN 模式或 UART 命令，不自动应用标定。Keil 工程包含它以检查构建，
当前 G431 不调用它，也不因它的存在开放控制许可。

调用方显式提供母线、电流、机械位置与速度，以及每拍的主动试验许可和已确认的电流校准。
模块只产生固定定子 αβ 电压的缓升、保持与三相 duty 意图；执行方仍须实现跨边界 staging、
enable、独立 deadline、实际关断及失败反馈。函数不再被调用时不能自行关断。

稳定窗口要求足够励磁、低速和整个窗口的有界位置跨度。位置按采集时间去重，跨零用圆差；
完整三相电流先作幅值不变 Clarke，公共模不能冒充有效励磁。时间异常、过流、反馈失效、
故障、总时限或 Stop 均撤销输出。成功同样撤销输出，终态不会自动重试。

结果记录稳定编码器位置，以及假设正、负编码器方向分别得到的两份 offset 候选：
`theta_e=wrap(pole_pairs*direction*position-offset)`。堵转、外力和静摩擦都可能产生静止，
单次静态结果不能确认方向、极对数、相序或电流极性；独立运动验证与实际时序验收后，
才由上层决定是否安装。供应商标称不会自动变为物理确认。

```powershell
.venv\Scripts\python.exe -X utf8 firmware/app/motor/tests/verify_rotor_alignment.py
```

测试执行正式 ARM C，覆盖时限、新鲜度、跨零窗口、公共模反例与独立理想转子模型。
这些结论不代表实际电机已完成定向或已具备功率运行条件。
